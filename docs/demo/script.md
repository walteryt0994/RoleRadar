# RoleRadar 演示讲稿

配合 [Demo 指南](README.md) 使用。演示前先按 [checklist.md](checklist.md) 准备一个全新的演示目录并启动。下面的按钮名、页面标题和提示语都是在新准备的合成预览里实际点过的（2026-11-19）。

## 讲之前记住三条

- **开场统一说**：“这次使用合成资料和模拟服务展示完整交互；真实模型与来源链路另有受控验证记录。”
- **数字以页面为准**：口播的数字只说这一次页面上显示的。按这份合成资料，正常会看到下文写的数字；页面不一样就说页面上的。
- **百分比叫“依据覆盖比例”**：
  - 它的意思是“列出的技能要求里，有多少条在你的经历里找到了依据”；
  - 不是录用概率，也不是综合适合度；
  - “暂缺依据”不等于不会；硬性条件冲突单独显示，不算进这个比例。

## A. 约 3 分钟录屏分镜

这一节是分镜，不是成片。录屏时用 1440×900 左右的浏览器窗口、100% 缩放、简体中文界面；等待的几秒可以剪掉。不录系统声音，旁白另录或现场说。

各段时长是按口播字数静态估算的（每段大约每秒 4 个字以内）。没有真人计时，也还没有录成片；实际录的时候按朗读速度微调。阶段编号、评估细节这类说明放在 D 节技术追问里，不挤进开场和结尾。

## D. 技术追问要点

**这是 Agent 吗？分工是什么？**

- 三层：
  - 普通业务逻辑（经历库、版本、偏好、岗位记录、决定、回收站、导出）；
  - 固定 AI 工作流（简历结构化、岗位分析、方向探索）：固定的请求步骤、固定的输出格式，本地检查结果；
  - 有边界的单 Agent，只用在发现岗位：最多 8 次决策，只能调用固定工具（检索、读取、核对、分析、结束），只在用户确认的范围里活动，不能自己放宽范围。
- 今天的演示里，哪些是真实运行的、哪些是模拟的：
  - 真实运行：第一层的本地业务逻辑。经历库、版本、保存、收藏和决定都由真实的程序处理，数据写进这台电脑上的 SQLite 文件，服务重启后还在。
  - 模拟实现：模型的回答（方向探索、岗位分析）和 Agent 每一步的决策，由本机模拟服务按固定规则给出；岗位来源是代码里的合成岗位。
  - 固定工作流和 Agent 的流程本身照常运行（发送前核对、本地核对引文、工具的范围和次数限制），换成模拟的只是“回答”和“来源”。
- 架构能力和评估结果要分开说：Agent 能根据工具结果调整下一步，这是能力；但在受控真实运行和对照里，**没有观察到有效的真实反馈调整轨迹，也没有观察到相对固定流程的收益**，这一项明确记为未满足。

**依据怎么保证不是编的？**

- 不能保证每条结论在语义上都正确。逐字核对能确认引文来自已发送的文字，不能单凭这一点证明它支持整条要求；本地规则也有识别边界，仍需用户复核。
- 结果里的每条引文都必须是发出去的原话，本地逐字核对。
- 句子的性质由本地规则判断：识别为队友做的、计划做的、否定的、只说“熟悉”的会降级；演示用例展示这些规则，不代表覆盖所有表达。
- 硬性条件单独列出，不知道就写“未知”。
- 保存的分析留着当时的引文和经历版本；经历改了，页面会提示依据已变。
- 页面上可以“反馈问题”：指出哪条判断不对，只记在本机。

**授权、次数、成本和取消怎么控制？**

- 发送前有核对页：列出接收方和要发的每一栏，用指纹把“确认的内容”和“实际发出的内容”绑在一起。
- 外发规则：遮盖联系方式，拦下疑似地址或标明保密的文字。
- 真实服务前面有一道关卡：每次运行要单独批准（用途、模型、次数、应用内预算、当天有效）；发送前预留费用并逐笔记账；用量未知就暂停；可以随时取消和停止。
- 应用内预算不是服务商账单硬上限；取消只能阻止后续请求，已经发出的请求不能撤回。
- 演示脚本用空环境启动，所以演示时一定是模拟服务。

**现在验证到哪一步，还有什么不足？**

- U3 只按 Owner 批准的当前范围阶段收尾，不是完整 U3 全部通过。第 9 项仍未满足，不再补跑；发布展示材料不进入 U4，也不代表部署。
- 离线测试：在提交 `90c8d09` 的代码上，Claude 冻结后的完整离线回归 4,671 项通过；Codex 独立跑相关的 17 个测试文件，402 项通过。都是当时的记录，没有持续集成。
- 真实模型（OpenAI 官方接口）和一个公开招聘网站的受控读取，只在几次小规模、单独批准的运行里验证过，用的都是合成资料。记录放在仓库外，不公开原始数据。
- 不足：
  - 没有部署，没有真实身份验证；
  - Agent 的收益没有被证明；
