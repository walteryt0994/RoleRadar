# RoleRadar Demo 指南（中文）

这一套材料用来把 RoleRadar 现在的样子清楚、如实地展示给朋友、招聘方或面试官：约 3 分钟录屏讲解，约 5 分钟现场演示。

**现在能展示什么**：在你自己的电脑上，用合成资料和本机模拟服务，完整走一遍“确认经历和偏好 → 探索方向 → 发现岗位或补充岗位 → 有依据的分析 → 保存与个人决定”。

**还没有什么**：没有录好的视频（这里只有录屏脚本和分镜），没有线上试用链接，也没有部署到任何平台。

## 三个入口

- **先读**：这一页，然后是演示前检查 [checklist.md](checklist.md)。
- **怎样启动**：下面的“准备和启动”，两条命令。
- **怎样照稿演示**：讲稿 [script.md](script.md)。里面有 3 分钟录屏分镜、5 分钟现场主线、备用短路径、技术追问要点，以及简短的英文开场、关键句和结尾。

开场统一说一句：**“这次使用合成资料和模拟服务展示完整交互；真实模型与来源链路另有受控验证记录。”**

## 准备和启动

需要 git 和 Python 3.13。脚本已在 macOS 验证；Linux、Windows/WSL 和全新环境安装尚未验证。

1. 从 `main` 获取当前演示版本，在新目录克隆，避免影响已有工作区：

```bash
git clone --branch main https://github.com/walteryt0994/RoleRadar.git RoleRadar
cd RoleRadar
```

2. 建虚拟环境、装依赖（只需一次，在仓库根目录）：

```bash
python3.13 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
```

3. 准备一个全新的演示目录。不写 `--dir` 时，默认放在 `~/roleradar-demo/demo-日期-时间`：

```bash
.venv/bin/python scripts/demo/prepare_demo.py
```

   - 几秒钟完成。最后一行会打印下一步的启动命令。
   - 目录已经存在就拒绝运行，不会覆盖任何东西。
   - 全程不联网，不读任何真实服务的配置。

4. 启动（把目录换成上一步打印的那个）：

```bash
scripts/demo/run_demo.sh ~/roleradar-demo/demo-日期-时间
```

   - 默认端口 8850，只监听本机。端口被占用时会提示，可以换一个，例如在命令末尾加 ` 8851`。
   - 启动时用空环境：shell 里的 API Key、真实来源设置都不会被读到。在 macOS 上还会套一层只许连本机的沙箱。

5. 浏览器打开 <http://127.0.0.1:8850>，点 **以合成用户 A进入**，进入“工作台”。

6. 停止：在运行命令的终端按 **Ctrl-C**。

7. 重置：再运行一次第 3 步，得到一个新目录，再用第 4 步启动它。旧目录原样保留；不想要了可以自己删，脚本从不删除任何东西。

## 演示资料：来源要分清

所有资料都是虚构的，标着“合成示例”。故事主角是**林夏（合成示例）**，统计学学生，找北京的数据分析实习。

- **原始资料**，由准备脚本按正常的网页提交流程录入，内容在 [fixtures/demo_story.json](fixtures/demo_story.json)：
  - 经历一，校园二手书交易数据分析（课程项目）：用 Python 清洗数据、用 SQL 汇总、用 Excel 做报表；还有一句“队友负责用 Tableau 做看板”。
  - 经历二，学院读书社招新报名改进（社团活动）：组织分工排进度、设计问卷、用 Excel 统计；还有一句“我计划下学期学习 Power BI”。
  - 求职偏好：
    - 方向：数据分析（理想）、用户研究（也可以接受）；
    - 城市：北京（理想）、上海（也可以接受）、深圳（不能接受）；
    - 类型：实习；不做销售；
    - 必要条件：最早 2027 年 1 月入职，每周可实习 4 天以上。
- **手动示例岗位**，即用户自己补充的岗位：[fixtures/supplied_jd.txt](fixtures/supplied_jd.txt)，“数据分析实习生（合成示例 JD）”，星河教育科技（合成公司）。
- **合成岗位来源**：发现岗位时搜到的“合成招聘官网 / 合成搜索线索”。这些岗位写在代码里，标题都带“合成岗位，不是真实招聘”，链接是不能访问的 `.invalid` 地址。
- **模拟生成的结果**：方向、分析、找岗的每一步决定，都由本机模拟服务按固定规则生成，页面上写着“本机模拟服务……不是 AI”。讲的时候说“模拟结果”，不要说成模型判断。

准备脚本还会**预先保存几条记录，供现场兜底**，都是走正常流程保存的：

- 一次保存的方向探索（没有做方向决定，留给现场），在“方向探索 → 探索记录”。
- 一份查找摘要，在“岗位机会 → 查找与分析记录 → 查找记录”。
- 补充的合成 JD 已加入“我的岗位”并标为收藏，备注写着“演示准备脚本预先保存的示例记录（合成），现场兜底用”；还有它的一份已保存分析。

演示目录里的 `demo-manifest.json` 记着这些记录的页面地址和准备时间。用到兜底记录时，口头说明“这是演示前预先保存的结果”。

## 结果的有效期

- 查找、探索、分析的结果页是临时的：保留 30 分钟（页面写着到期时间），服务重启后就没有了。只有点了“保存”的才留下。
- 演示前不要提前跑好结果、开着页面等。现场跑只要几秒；如果超过 30 分钟，重新跑一次即可。
- 现场来不及或结果过期时，切到预先保存的记录，并说明是预先保存的，不能说成刚刚生成的。

## 已知限制（讲之前心里有数）

- U3 只按 Owner 批准范围阶段收尾，**不是完整 U3 全部通过**。第 9 项“真实来源上的有效反馈调整轨迹”仍未满足，不再为本次收尾补跑；演示包发布不代表部署，也不进入 U4。
- 本机模拟规则很粗：
  - 只认一组固定的技能词（例如 SQL、Python、Tableau、Power BI、Machine Learning）；
  - 方向探索的依据常引用标题或场景这类短句；
  - 引用哪一句，取决于经历的随机编号顺序，每次准备可能不同。
  - 所以讲稿只写确定会出现的内容。
- 合成岗位的发布和截止日期写死在 2026 年 10 月到 12 月。以后再演示，页面会照样显示这些日期。过了截止日期以后，不要对它们点“更新跟踪中的岗位”或单个岗位的核对：会按截止日期显示为关闭。
- 补充岗位时，如果预先保存的同一份 JD 还在，预览页会提示“有一模一样的”。这是去重功能，直接点“分析岗位”即可，不用另存。
- 界面可以切成英文（用户菜单里的 English），但合成资料是中文写的。英文界面下新跑的结果，说明文字是英文，原文不翻译。
- 开发登录不是真实身份验证，只能在本机用；不要在演示库里输入真实个人信息。
